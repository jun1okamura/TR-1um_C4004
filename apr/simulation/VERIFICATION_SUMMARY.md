# C4004 フルチップ実レイアウト抽出後 (Post-Layout Extracted) 検証・FMAX・統計サマリ

本ドキュメントは、OpenSUSI **TR-1um (1 µm CMOS, 2M1P, 5.0 V)** プロセスで設計・自動配置配線・サインオフ検証を完了した **Intel 4004 完全互換 4-bit CPU (`C4004` / `tr_1um_jun1okamura`)** について、KLayout LVS が実レイアウト GDSII (`apr/c4004_chip.gds`, `src/tr_1um_jun1okamura.gds`) から抽出したフルチップネットリスト (`apr/OSS_FRAME.extracted` → `apr/OSS_FRAME_sim.spice`) を用いた **`ngspice` ポストレイアウト検証結果、クリティカルパス最適化解析、および物理・回路統計** をまとめたものです。

## 1. エグゼクティブサマリ & Trial-10 からの性能向上比較

Trial-10 (`TR-1um_C4004_10`) のボトルネックであった **(1) `X1` フェーズの `SRAM128` プリリード (`sram_do[3:0] -> reg_buf[3:0]`) パスの2段ゲート遅延＋配置座標不整合 (`1,200 µm` 横断配線)** および **(2) `M1` フェーズの双方向バスターンアラウンド (`d_hiz` / `d_oe`) パスの6段ゲート遅延 (`NOR4` 直列 PMOS 4段)** を抜本的に再設計した結果、すべての主要指標で Trial-10 を上回る過去最高性能を達成しました。

| 評価指標 | 初期 9行ベースライン | Trial-10 (`C4004_10`) | **本設計 (Redesigned)** | Trial-10 比改善量 |
| :--- | :---: | :---: | :---: | :---: |
| **フルチップ最大動作周波数 (`FMAX`)** | `15.0 MHz` (`66.7 ns`) | `19.0 MHz` (`52.6 ns`) | **`21.0 MHz` (`47.62 ns`)** | **`+2.0 MHz` (`+10.5%` 高速化)** |

## 2. Trial-10 のボトルネック原因解析と再設計アーキテクチャ

### 2.1 ボトルネック①：`X1` フェーズ `SRAM128` プリリードパス (`19.5 MHz` で `ACC = 0x5` 誤動作)
- **Trial-10 の問題点**:
  1. `clk = 0`（後半ハーフサイクル、`19.5 MHz` で `25.64 ns`）中に `SRAM128` から読み出された `sram_do[3:0]` が、`NAND2 (_0821_.._1009_)` → `NAND3 (_0824_.._1011_)` の **2段の組合せゲート** を経由してから `reg_buf[3:0]` (`MUXDFFRB _1143_.._1146_.B`) に入力されていた。
  2. `sram_ce` を駆動する `_1102_` が3入力 `NOR3` で構成されており、`clk` 立下りから `sram_ce` 立上りまでの遅延が大きかった。
  3. `scripts/run_tap2_flow.py` 内のアンカー座標にタイポ (`480.0`) があり、`_1143_.._1146_` が西側 (`X = 291..626 µm`) に押し出され、東側の `u_sram.DO[3:0]` (`X = 1353..1505 µm`) から **`1,200 µm` 以上の長距離配線** が発生していた（同時に16個の FF が本来の行から押し出され、総配線長が `+19,963 µm` 増加していた）。
- **本設計での解決策**:
  1. **ゼロゲート直結 (`sram_do[3:0] -> MUXDFFRB.A`)**: `X1` プリリード選択信号 `rb_sram_sel_n = !(_0283_ & _0307_)`（`clk` 立上りの `20 ns` 以上前に確定するフルサイクル信号）を `NAND2 u_rb_sram_sel_n` で生成し、`MUXDFFRB _1143_.._1146_` の選択端子 `.S` に接続。`S = 0` で選択される `.A` 入力に **`sram_do[0..3]` を組合せゲート0段で直結** し、フルサイクル余裕のある保持・ライトバック経路のみ `u_rb_mux0..3` 経由で `.B` (`S = 1`) に入力。
  2. **`sram_ce` 2入力 `NOR2` 化＋マクロ直下配置**: `rst_n` 条件を前段の `NAND4 _1101_` に統合し、`_1102_` を高速な2入力 `NOR2 (.A(_0534_), .B(clk_in_th), .Y(sram_ce))` に変更。さらに `_1101_` (`X = 1458.0 µm`) と `_1102_` (`X = 1501.2 µm`) を Row 10 東側の `u_sram.CE` (`X = 1504.6 µm`) 直下に固定配置。
  3. **`reg_buf[3:0]` 東側配置と FF 行割当の完全整合**: `FF_TARGET_PER_ROW = [3, 2, 2, 4, 4, 4, 6, 6, 4, 3, 3]` により `_1143_.._1146_` を Row 6 東側 (`X = 939.6..1323.0 µm`) に配置し、残り37個の FF すべてを行移動ゼロ (`0` row displacement) で配置。これにより総配線長を **`-18,831 µm` 短縮 (`431,812 µm`)**、ビア数を **`-153` 個削減 (`2,832` 個)**。

### 2.2 ボトルネック②：`M1` フェーズ `d_hiz` / `d_oe` バスターンアラウンドパス (`20.0 MHz` で `ACC = 0x0` 誤動作)
- **Trial-10 の問題点**:
  - `A3 -> M1` 遷移 (`phase: 2 -> 3`) において、コアの出力バッファを Hi-Z に切り替える `d_hiz` およびモニタ出力 `d_oe` が、`phase_0 -> u_fobuf -> NOR3 _0877_ -> OR2 _0878_ -> NOR4 _1071_ (直列 PMOS 4段!) -> u_buf_dhiz -> INV_X1 _1072_ -> u_buf_doe` という **計6段の深い論理段数** を通過していたため、`t_pd(d_oe) = 45.47 ns` を要し、`20.0 MHz` (`T_clk = 50.0 ns`) で外部 ROM データ取り込みに間に合わなかった。
- **本設計での解決策**:
  - `phase[2:0]` FF の反転出力 `.QB` (`_0008_, _0009_, _0555_`) から直接デコードする **2段並列論理** に刷新：
    - `OAI21 u_n_a123 (.A1(_0009_), .A2(_0555_), .B(_0008_), .Y(n_a123))`
    - `NOR2 u_n_x23_oe (.A(_0390_), .B(_0394_), .Y(n_x23_oe))`
    - `AND2_X1 _1071_ (.A(n_a123), .B(n_x23_oe), .Y(d_hiz_pre))` → 西辺 `u_buf_dhiz` (`X = 64.8 µm, Y = 318.6 µm`) の隣 (`X = 81.0 µm, Y = 318.6 µm`) に隣接配置 (`FO = 1`)。
    - `NAND2 _1072_ (.A(n_a123), .B(n_x23_oe), .Y(d_oe_pre))` → 南辺 `u_buf_doe` (`X = 1009.8 µm, Y = 27.0 µm`) の隣 (`X = 993.6 µm, Y = 27.0 µm`) に隣接配置 (`FO = 1`)。
  - これにより **`t_pd(d_oe)` は `45.47 ns` から `31.97 ns` へ `-13.50 ns` (`-29.7%`) 短縮** され、`21.0 MHz` (`T_clk = 47.62 ns`) まで完全に動作することを確認。

## 3. 実レイアウト抽出ネット (`OSS_FRAME_sim.spice`) 機能検証結果 (Test 1 〜 Test 3)

KLayout LVS で抽出した `apr/OSS_FRAME.extracted` を `scripts/prep_spice_sim.py` で変換した `apr/OSS_FRAME_sim.spice` に対し、全出力パッドに `1.0 pF` 負荷容量を接続して `ngspice` トランジェント解析を実施しました。

### 3.1 Test 1: ALU・アキュムレータ命令群 & `DCL` RAM バンク選択 (`apr/sim_test1_alu.sp` @ `1.0 MHz`)
- **実行プログラム**: `LDM 5 (0xD5)` → `IAC (0xF2)` → `CMA (0xF4)` → `DCL (0xFD)` (`ACC=0x9` → `cm_ram[3:0] = ~0x9 = 4'b0110` 選択検証) → `RAL (0xF5)` → `WRR (0xE2)` (`ACC = 0x3` 出力)
- **実測結果 (`apr/sim_test1_alu.log`)**: **PASS**
  - `WRR` 実行時の `X2` フェーズバス出力: **`D[3:0] = 0x3`** (`D3=0.00V, D2=0.00V, D1=5.00V, D0=5.00V`), **`d_oe = 5.00V`** (期待値 `0x3`, `5.00V`)
  - `DCL` 実行後の `A3` フェーズ `cm_ram[3:0]` 出力: **`[5.00V, 0.00V, 0.00V, 5.00V]`** (期待値 `[5V, 0V, 0V, 5V]`)
  - `A3` フェーズ `cm_rom` 出力: **`0.00V`** (期待値 `0V`), `X3` フェーズ `sync` 出力: **`5.00V`** (期待値 `5V`)

### 3.2 Test 2: `SRAM128` インデックスレジスタ Read/Write (`apr/sim_test2_sram.sp` @ `1.0 MHz`)
- **実行プログラム**: `FIM P0, 0xA5 (0x20, 0xA5)` (`R0=0xA, R1=0x5` を `SRAM128` に書込) → `INC R1 (0x61)` (`R1=0x6`) → `SRC P0 (0x21)` (`X2` で `R0=0xA`, `X3` で `R1=0x6` をバス出力) → `LD R0 (0xA0)` → `ADD R1 (0x81)` (`0xA + 0x6 = 0x0, CY=1`) → `BBL/LDM/ADD` 検証 → `WRR (0xE2)` (`ACC = 0xF` 出力)
- **実測結果 (`apr/sim_test2_sram.log`)**: **PASS**
  - `SRC P0` (`X2` フェーズ `R0` 出力): **`0xA`** (期待値 `0xA`)
  - `SRC P0` (`X3` フェーズ `R1` `INC` 後出力): **`0x6`** (期待値 `0x6`)
  - `WRR` (`X2` フェーズ `ACC` 出力): **`0xF`** (期待値 `0xF`)

### 3.3 Test 3: `SRAM128` サブルーチンスタック (`JMS`/`BBL`) & `JCN` 条件分岐 (`apr/sim_test3_stack_jcn.sp` @ `1.0 MHz`)
- **実行プログラム**: `JMS 0x123 (0x51, 0x23)` (戻り番地 `0x002` を `SRAM128` スタックに保存し `PC=0x123` へジャンプ) → `BBL 0x9 (0xC9)` (`SRAM128` スタックから `PC=0x002` を復帰し `ACC=0x9` をロード) → `JCN C0=1(test==0), 0x45 (0x11, 0x45)` (`P10(test)=0V` を検出して `PC=0x045` へ分岐) → `WRR (0xE2)` (`ACC=0x9` をバス出力)
- **実測結果 (`apr/sim_test3_stack_jcn.log`)**: **PASS**
  - `JMS` 分岐直後のフェッチアドレス (`A1..A3`): **`PC = 0x123`** (期待値 `0x123`)
  - `BBL` 復帰直後のフェッチアドレス (`A1..A3`): **`PC = 0x002`**, **`ACC = 0x9`** (期待値 `0x002`, `0x9`)
  - `JCN (test=0)` 分岐直後のフェッチアドレス (`A1..A3`): **`PC = 0x045`** (期待値 `0x045`)
