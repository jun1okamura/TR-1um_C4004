# C4004 フルチップ実レイアウト抽出後 (Post-Layout Extracted) 検証・FMAX・統計サマリ

本ドキュメントは、OpenSUSI **TR-1um (1 µm CMOS, 2M1P, 5.0 V)** プロセスで設計・自動配置配線・5項目サインオフ検証を完了した **Intel 4004 完全互換・MCS-4 フル準拠 (`25/25`) 4-bit CPU (`C4004` / `tr_1um_jun1okamura`, Plan B v2)** について、KLayout LVS が実レイアウト GDSII ([`c4004_chip.gds`](../c4004_chip.gds), [`tr_1um_jun1okamura.gds`](../../src/tr_1um_jun1okamura.gds)) から抽出したフルチップネットリスト ([`OSS_FRAME.extracted`](../OSS_FRAME.extracted) → [`OSS_FRAME_sim.spice`](../OSS_FRAME_sim.spice)) を用いた **`ngspice` ポストレイアウト検証結果、4チップ統一ベンチマーク比較、クリティカルパス物理波形解析、および物理・回路統計** をまとめたものです。

## 2. アーキテクチャ・物理実装における 6つの最適化と波形解析

### 2.1 半周期 `negedge -> SRAM128 -> Pad` パスの完全撤廃（`10.53 MHz` → `28.50 MHz`）
- 旧再設計版では `BBL` 復帰直後の `A1..A3` および `SRC` の `X3` フェーズにおいて、後半ハーフサイクル (`clk = 0`) で `SRAM128` から読み出したデータをそのまま同一サイクル内に出力パッド `D[3:0]` へ駆動していたため、`All88` で `10.53 MHz`、`PartA` で `12.50 MHz` に律速されていた。
- **Plan B v2 ([`c4004_core.v`](../../rtl/c4004_core.v))**:
  1. 12-bit `PC` を常時 DFF (`buf_l`, `buf_m`, `buf_h`) で保持し、`SRAM128` へのスタック退避書込を **`JMS` 第2サイクルの `M1`〜`X1` のみにオンデマンド化**。
  2. `BBL` では `M2` 後半・`X1` 後半・`X2` 後半の3ステップでスタックから復帰アドレス3ニブルを順次プリリードして `buf_l`, `buf_m`, `buf_h` に格納し、次サイクル `A1..A3` では 100% FF 直出しとした。
  3. `SRC` でも `M2` 後半と `X1` 後半に `R[2P]` / `R[2P+1]` を先行プリリードして `u_ff_sram_lat0..3` から駆動することで、**半周期パッド出力パスを完全に 0本化** した。

### 2.2 パッド直近アンカー配置の 12個 純 `DFFRB` 出力レジスタ
- `D[3:0]`, `d_oe`, `d_hiz`, `sync`, `cm_rom`, `cm_ram[3:0]` の全外部出力信号を1ステート前に事前計算し、`MUXDFFRB` より内部遅延が約 `3.5 ns` 短い **純 `DFFRB` 12個** (`u_ff_dout0..3`, `u_ff_doe`, `u_ff_dhiz` + `u_buf_dhiz`, `u_ff_sync`, `u_ff_cmrom`, `u_ff_cmram0..3`) にラッチ。
- [`run_tap2_flow.py`](../../scripts/run_tap2_flow.py) でこれら12個の `DFFRB` を各辺の対応 I/O パッド直近に固定アンカー配置した結果、全出力ピンのパッド伝搬遅延 (`P1` `2.5 V` ↑ → パッド `2.5 V`、`CL = 1.0 pF`) を **`20.11 〜 23.48 ns`** まで短縮・均一化した。

### 2.3 事前計算レジスタ駆動 `SRAM128` 制御インターフェースとホールドマージン確保
- `SRAM128` のアドレス `sram_addr_q[4:0]`、チップセレクト許可 `sram_idle_q` (`u_ff_sram_idle`)、ライトイネーブル `sram_we_n_q` (`u_ff_sram_wen`) を1フェーズ前にレジスタ確定させ、`X3 -> A1` 遷移時の組合せデコードグリッチによる誤書込を根絶。
- さらに `WR` 信号に `u_buf_sram_we` (`BUF_X2`) を挿入し、`SRAM128.lib` が要求する `CE↓` 後のホールド時間（`WR >= 1.0 ns`, `DIN >= 3.0 ns`）を実レイアウト抽出波形上で確実に満足させた。

### 2.4 `PC+1` 専用インクリメンタ (`pc_inc`) と `X2` 4-bit CLA の分離
- `A1..A3` フェーズの `PC+1` 演算を専用並列キャリー回路 `pc_inc` に分離したことで、`X2` フェーズの 4-bit CLA 入力 `alu_a` を 4:1 MUX から最小 2:1 MUX (`sram_lat` / `acc`) に簡素化し、ALU クリティカルパス段数を削減した。

### 2.5 `FO=1` `SRAM128` 専用キャプチャ FF (`u_ff_sram_lat0..3`) + Useful Clock Skew の実波形挙動
- `u_sram.DO[3:0]` の真下（Row 10 東側）にファンアウト `FO=1` の純 `DFFRB` 4個 (`u_ff_sram_lat0..3`) を密着配置し、そのクロック `clk_sram_lat` に `3 × BUF_X2` (`u_clk_sram_lat1..3`) の Useful Clock Skew を挿入した。
- **ポストレイアウト `ngspice` 実波形解析 (`25 MHz`, `T_clk = 40.0 ns`)**:
  - 後半ハーフサイクル (`clk = 0`, `t = -20.0 ns`) で `P1` が立ち下がると、`+12.1 ns` 後に内部 `sram_ce` が立ち上がり、`SRAM128` のプリチャージを経て `P1` 立上りから **`+9.4 ns` 後**（`28.5 MHz` でも **`+11.9 ns` 後**）に `DO[3:0]` が確定する。
  - 通常行クロック (`clk_buf_r7`) は `P1` 立上りから `+11.5 ns` で立ち上がるのに対し、`3 × BUF_X2` を経た `clk_sram_lat` は **`+20.0 ns`** で立ち上がり (`+8.5 ns` の実効スキュー)、`sram_lat[3:0]` 出力 `.Q` は **`+23.8 ns`** に確定する。これにより `28.5 〜 29.0 MHz` (`T_clk / 2 = 17.2 〜 17.5 ns`) の高速領域でも `SRAM128` 読出データを十分なセットアップ余裕（`> +7.8 ns`）で確実にキャプチャできる。
  - 一方、次ステート `X2` で `sram_lat -> 4-bit CLA -> acc` に使える時間窓は `T_clk + 12.0 ns - 23.8 ns = T_clk - 11.8 ns` となる。通常のレジスタ加算・インクリメント・比較 (`All88` / `ALU72`) は `23.2 ns` 以内に完了するため **`28.50 〜 29.00 MHz` まで単調に 100% PASS** する。`Test 4` のように `SRAM128` `1→0→1` 読出直後に **4-bit 全桁キャリー伝搬 (`4'b1001 + 4'b0111 = 5'b10000`)** が重なる最悪合成コーナーのみ `sram_lat[0] -> c1 -> c2 -> c3 -> xor3 -> acc[3]` に約 `32.2 ns` を要するため、単調上限が **`22.50 MHz` (`T_clk = 44.44 ns`)** となる（将来この `3 × BUF_X2` を `1 × BUF_X2` に詰めれば両方 `28.5 MHz` 付近で均衡可能）。

### 2.6 MCS-4 システム仕様 `25/25` 完全準拠プロトコル
- 2段ポジティブエッジ・リセット同期化 (`rst_s1`, `rst_s2`) と 32クロック自動 `SRAM128` 全番地ゼロクリアにより、リセット解除後 **33クロック目で `sync = 1`、34クロック目から `PC = 0x000` (`A1`)** を開始。
- Active-High `cm_rom`、3-bit `DCL` 全8バンク選択 `cm_ram[3:0]` (`3'd0 -> 4'b0001`, 非ゼロ `-> {dcl_reg, 1'b0}`)、および `X1` での `OPA` エコー出力 (`d_oe = 1`) を完全実装。

## 3. 実レイアウト抽出ネット (`OSS_FRAME_sim.spice`) 機能検証結果 (Test 1 〜 Test 3)
