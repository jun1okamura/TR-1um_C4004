     - `CE ↑` → `PRn ↑`（プリチャージ解除）: `+1.91 ns`

### 2.2 `reference/07_sram6t_macro.md` の想定と実マクロ `SRAM128` の仕様差（RTL設計上の最重要ポイント）

`reference/07_sram6t_macro.md` §6〜§8 の計画時点と、完成した [SRAM128](file:///Users/okamura/Dropbox/98_LSI_Design/TR-1um_C4004/module/SRAM128/SRAM128.lib) の間には以下の動作仕様の違いがあり、RTL 設計でこれを正しく反映する必要があります。

| 項目 | `07_sram6t_macro.md` での当初想定 | 完成した実マクロ `module/SRAM128/SRAM128` |
| :--- | :--- | :--- |
| **セル名・ピン名** | `C4004_SRAM32X4`<br>`A[4:0], DIN[3:0], DOUT[3:0], WE, CE, CLK` | **`SRAM128`**<br>`CE, WR, A0, A1, A2, A3, A4, DIN[3:0], DO[3:0], VDD, VSS` |
| **クロック / トリガ** | `CLK` 1サイクル内で自動的に前半 Read + 後半 Write（RMW）を生成 | **`CE` の立ち上がりエッジ（`0 → 1`）1回につき Read（`WR=0`）または Write（`WR=1`）のどちらか1回を実行**（`CE=0` の期間にビット線プリチャージ） |
| **読み出し出力 `DO[3:0]`** | レベルセンス（マクロ外に `DLATCH` が必要と想定） | **マクロ内部（`SA` + `SACTR`）に出力ラッチを内蔵**。Read サイクル（`CE↑, WR=0`）から `6.5 ns` で確定し、**次の Read サイクルまで（`CE=0` 期間中も Write サイクル中も）値を保持する** → **外部ラッチ不要** |

#### RTL での `SRAM128` 制御・アクセス方式の選択肢

実マクロ `SRAM128` は **1回の `CE` 立ち上がりで Read または Write の一方のみ**を行うため、以下のいずれかの方式で RTL を構成します：

- **方式 A（推奨・完全単相クロック 1ステート1アクセス：`CE = ~CLK & sram_ce`）**:
  - CPU の全 FF は `posedge CLK` で更新し、`CLK = 1`（前半 `667 ns`）の間に `CE = 0`（`SRAM128` プリチャージ）＆アドレス・書込みデータ確定、`negedge CLK`（`CE ↑`）で `SRAM128` の Read または Write を実行する。
  - **セットアップ時間 `667 ns`、ホールド時間 `667 ns`、パルス幅 `667 ns`** となり、遅延セルによるパルス生成に頼らず最も堅牢に動作する。
  - この場合、1ステートにつき SRAM アクセスは 1回となるため：
    - **案 A-1（PC 12bit を FF に置き、Scratchpad 16×4b + サブルーチンスタック 3×12b を `SRAM128` に格納）**:
      - `A1..A3` では FF 上の `PC[11:0]` を出力＆インクリメントする。
      - `SRAM128` は `JMS`（`X1..X3` で戻り番地 3ニブルを Write）、`BBL`（`X1..X3` で戻り番地 3ニブルを Read）、および Scratchpad 命令（`X1` で Read、`X2` で Write 等、1命令最大2アクセス）のみで使用する。
      - **全46命令において 1ステート1アクセスで競合ゼロ**（特に `JIN P` や `FIN P` で `X1, X2` に Scratchpad を2回読む命令でも `PC` とのポート競合が一切起きない）。
    - **案 A-2（PC を含む全4段スタック 4×12b + Scratchpad 16×4b をすべて `SRAM128` に格納し、8ステートにパイプライン割当）**:
      - 1マシンサイクル（8ステート: `A1..X3`）の中で、PC Read 3回 + PC Write 3回 + Scratchpad 最大2回 = 計8アクセスを各ステートに割り当てる（`PC+1` の下位・中位ニブルを一時保持する 8bit FF と、`JIN`/`FIN`/`JUN`/`JMS` 時のバイパス制御が必要）。
- **方式 B（1ステート内で Read → Write の 2回 `CE` を叩く方式）**:
  - 外部クロックを 2倍周波数（`1.5 MHz`、16クロック＝8ステート）にするか、クロック両エッジ＋遅延セルで `CE` パルスを1ステートに2回出す方式。`07_sram6t_macro.md` §7 の RMW スケジュールそのままとなる。

## 3. Intel 4004 (`C4004`) RTL 仕様の整理

### 3.1 ピン割り当て（16ピン = 信号14本 + 電源2本）

`reference/06_design_policy.md` §2 およびオリジナル Intel 4004 DIP-16 ピン配置との対応案：

| DIP/Frame Pin | オリジナル 4004 | `OSS_FRAME_GIO` パッド | C4004 信号名 | 方向 | `OSS_ESD_5V_DIO` 接続 (`HIZ`, `OUT`, `P`) |
| :-: | :---: | :---: | :---: | :---: | :--- |
| **1** | `D0` | `P1` | `D[0]` | `inout` | `HIZ1 = ~d_oe`, `OUT1 = d_out[0]`, `d_in[0] = P1` |
| **2** | `D1` | `P2` | `D[1]` | `inout` | `HIZ2 = ~d_oe`, `OUT2 = d_out[1]`, `d_in[1] = P2` |
| **3** | `D2` | `P3` | `D[2]` | `inout` | `HIZ3 = ~d_oe`, `OUT3 = d_out[2]`, `d_in[2] = P3` |
| **4** | `D3` | `P4` | `D[3]` | `inout` | `HIZ4 = ~d_oe`, `OUT4 = d_out[3]`, `d_in[3] = P4` |

> **※ピン配置の確認事項**:  
> オリジナルの 4004 DIP-16 は `Pin 5 = VSS`, `Pin 12 = VDD` ですが、`OSS_FRAME_GIO` は **`Pin 8 = VSS`, `Pin 16 = VDD` にハードマクロ固定**されており、さらに **`SRAM128` マクロ（幅 `1166 µm`）のピン（`CE, WR, A0..A4, DIN, DO`）との配線距離**も関わります。14本の信号ピン（`D[3:0]`, `SYNC_N`, `CM_ROM_N`, `CM_RAM_N[3:0]`, `TEST`, `RESET_N`, `CLK`, 予備1本）の `P1..P7, P9..P15` への具体的な割り当て番号を決定します。

### 3.2 命令セット（全46命令）と実行サイクル

- **8ステート / 1マシンサイクル**: `A1 → A2 → A3 → M1 → M2 → X1 → X2 → X3`
  - `SYNC_N`: `X3` の間 Low（または Active-Low 同期パルス）を出力。
  - `A1, A2, A3`: ROM アドレス下位 `PC[3:0]` → 中位 `PC[7:4]` → 上位 `PC[11:8]` を `D[3:0]` に出力（`A3` で `CM_ROM_N` 出力）。
  - `M1, M2`: ROM から命令上位 `OPR[3:0]` (`M1`)、下位 `OPA[3:0]` (`M2`) を `D[3:0]` からフェッチ。2バイト命令（`JUN`, `JMS`, `JCN`, `FIM`, `ISZ`）および2サイクル命令（`FIN`）の1サイクル目では `M2` で2サイクル目フラグをセット。
  - `X1, X2, X3`: 命令実行、Scratchpad アクセス、`SRC` アドレス送出（`X2, X3`）、RAM/IO リード・ライト（`X2`）。
- **全46命令の分類**:
  1. **基本制御・分岐 (6命令)**: `NOP`, `JCN` (2cyc), `JUN` (2cyc), `JMS` (2cyc), `BBL`, `JIN`
  2. **インデックスレジスタ対・間接 (3命令)**: `FIM` (2cyc), `SRC`, `FIN` (2cyc)
  3. **インデックスレジスタ演算 (6命令)**: `ADD r`, `SUB r`, `LD r`, `XCH r`, `INC r`, `ISZ r` (2cyc)
  4. **I/O・RAM アクセス (16命令)**: `WRM`, `WMP`, `WRR`, `WPM`, `WR0..WR3`, `SBM`, `RDM`, `RDR`, `ADM`, `RD0..RD3`
  5. **アキュムレータ操作 (14命令)**: `CLB`, `CLC`, `IAC`, `CMC`, `CMA`, `RAL`, `RAR`, `TCC`, `DAC`, `TCS`, `STC`, `DAA`, `KBP`, `DCL`

## 5. `stdcell/v59_4` 調査・C4004 RTL実装・論理合成および検証結果

### 5.1 確定したアーキテクチャ方針
1. **クロック・メモリアクセス方式**:
   - 単相クロック `CLK`（標準 `750 kHz`, 1周期 `1.333 µs`）、1マシンサイクル = 8ステート（`A1, A2, A3, M1, M2, X1, X2, X3`）。
   - `SRAM128` は **1ステートにつき最大1回アクセス**（`clk = 1` の前半 `667 ns` でプリチャージ `CE = 0`、`clk = 0` の後半 `667 ns` で `CE = (~clk) & rst_n & sram_ce_en = 1` をアサートし、次ステートの `posedge clk` で `DO[3:0]` をラッチ）。
   - アクティブ `PC[11:0]` は FF（12 bit）で保持し、`A1..A3` ステート中に既存の4ビット加算器を時分割共用して `+1` インクリメントする。
   - `SRAM128`（`32 word × 4 bit`）のアドレス空間割り当て：
     - `A[4:0] = 0x00..0x0F` (`{1'b0, idx_reg[3:0]}`): インデックスレジスタ `R0..R15`（16 × 4 bit）
     - `A[4:0] = 0x10..0x1F` (`{1'b1, nib[1:0], sp[1:0]}`): サブルーチン戻り番地スタック（3段 × 12 bit、`JMS` の `A1..A3` で `PC+1` を書き込み、`BBL` の `M2..X2` で読み出して `PC` に復帰）
2. **14番目の信号パッド（予備ピン `P15`）の用途**:
   - デバッグ・ステータス観測出力 `cy_out`（キャリーフラグ `cy` の直接出力、`HIZ15 = 0` 固定出力）。
3. **スタンダードセルライブラリ**:
   - `TR-1um_APRtools` の **`stdcell/v59_4`**（`tr1um_typ_5v0_25c.lib` / `tr1um_stdcell.gds`）を使用。

### 6.2 OpenROAD による 2層メタル制約（STDCELL 上の M1 通過禁止）P&R 収束
- **物理制約**:
  - `stdcell/v59_4` は内部配線に `METAL1` を使用しており、標準セルの上を水平 `METAL1` で通過することはできない（`VSS` レール `y = 1.1..3.7 µm`、`VDD` レール `y = 55.7..58.3 µm`）。
  - したがって、**水平 `METAL1` 配線はすべて標準セル行間の配線チャネル（Routing Channel）内のみを通し、標準セルの信号ピンへは垂直 `METAL2` のみでアクセスする**必要がある。
- **OpenROAD 設定の要点**:
  1. **DRT 用セル LEF (`TR-1um_cells_m2only.lef`)**:
     - 全標準セルに `OBS LAYER METAL1 ; RECT 0.000 1.100 <width> 58.300 ;` を設定し、標準セル内部の 11 本の水平 `M1` トラック（`y_rel = 2.7 .. 56.7 µm`）を 100% ブロック。これにより、隣接チャネルの最外トラック（`y_rel = -2.7 µm`, `62.1 µm`）上の `via_1` パッド（`3.4 × 3.4 µm`）との間に `2.1 µm`（`>= 1.4 µm` M1 最小間隔）のクリアランスを確保。
     - 標準セルの全信号ピンを `LAYER METAL2`（`y_rel = 28.0..31.4 µm`）のみに定義。
  2. **完全単方向配線制約 (`detailed_route_set_unidirectional_layer`)**:
     - OpenROAD 26Q4 の以下のコマンドを適用：
       ```tcl
       detailed_route_set_unidirectional_layer METAL1
       detailed_route_set_unidirectional_layer METAL2
       ```
     - これにより、`TritonRoute` が標準セル行内で水平 `METAL2` ジョグや垂直 `METAL1` ジョグを生成することを完全に禁止（`Wrong-way vertical METAL1 = 0`, `Wrong-way horizontal METAL2 = 0`）。
  3. **9 行 + `118.8 µm`（22 トラック）ワイドチャネル・フロアプラン**:
     - コア領域 `21.6 0.0 1819.8 1805.6` 内に `u_sram` (`SRAM128`) を `(334.8, 1596.0)` に配置。

## 7. 統合前の FMAX 解析および `OSS_FRAME_GIO` ユーザースペース (`1.8 × 1.8 mm`) 収容性検証

### 7.1 統合前の FMAX（最大動作周波数）解析
- **クリティカルパスの構造（半周期パス `a = 0.50`）**:
  - `c4004_core` では、`u_sram/CE` が `AND3_X1 _1043_` (`sram_ce = sram_ce_en & ~clk & rst_n`) によって生成され、**クロック立下りエッジ (`negedge clk`, `t = T/2`) で立ち上がり**、`u_sram/DO[3:0]` の読み出しデータが ALU / 演算経路を経由して **次のクロック立上りエッジ (`posedge clk`, `t = T`) で `acc[3:0]` 等の FF（最悪エンドポイント `_1151_/D` `acc[3]`）にラッチ**される。
  - したがって、最悪 `reg -> reg` パス（`u_sram/CE -> u_sram/DO[0] -> u_buf_sram_do_0_0 -> ... -> _1151_/D`）に与えられる時間予算は **半周期 (`T/2`, 周期係数 `a = 0.50`)** となる（`TR-1um_APRtools/syn/sta/report.tcl` の2点法に準拠）。
- **OpenROAD / OpenSTA 実測結果（`apr/c4004_core_buffered_routed.def`, `tr1um_typ_5v0_25c.lib` + `SRAM128.lib`, `5.0 V`, `25 ℃`）**:

| 解析条件 | 半周期パス実遅延 (`T/2` 要求値) | 最小クロック周期 `T_min` | 最大動作周波数 **`FMAX`** | 750 kHz (`1333.3 ns`) 比マージン |
| :--- | :---: | :---: | :---: | :---: |
| ① **Ideal Clock・配線RCなし** (`syn/sta/setup.tcl` 基準) | `50.723 ns` | **`101.446 ns`** | **`9.86 MHz`** | **13.1 倍** |
| ② **Propagated Clock（`BUFTH` + 行 `BUF_X2` ツリー）・配線RCなし** | `59.058 ns` | **`118.116 ns`** | **`8.47 MHz`** | **11.3 倍** |
| ③ **Propagated Clock + 実配線RC付加** (`0.20 fF/µm`, `50 mΩ/µm`) | `71.211 ns` | **`142.422 ns`** | **`7.02 MHz`** | **9.4 倍** |

- **内訳（条件③：Propagated Clock + 実配線RC `0.20 fF/µm` 適用時、`T = 1333.0 ns`）**:
  - Launch（`negedge clk` `666.500 ns` + `clk -> u_bufth_clk -> _1043_ -> u_sram/CE` 伝播遅延 `20.645 ns`）= `687.145 ns`
  - `SRAM128` Read Access (`CE ↑ -> DO[0] ↑`) = `17.999 ns`
  - 組合せ論理（`u_buf_sram_do_0_0` 〜 ALU `XNOR2 _0765_` 〜 `u_buf_n_0311_0` 〜 `_0788_`）= `40.508 ns`
  - データ到着時刻 (`_1151_/D`) = `745.652 ns`
  - Capture（`posedge clk` `1333.000 ns` + クロック伝播遅延 `8.950 ns` - Setup `1.009 ns`）= `1340.941 ns`
